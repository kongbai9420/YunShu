# 监控、告警与巡检

## 指标

- 每台资产的“指标与采集”显示最新值、质量（有效、估算、失败、不支持、未配置、过期）和来源协议。
- 历史曲线自动选择精度：原始数据保留 48 小时，分钟汇总 30 天，小时汇总 1 年（可在 [配置项](configuration.md) 调整）。
- 页面通过实时推送更新，无需手动刷新；顶栏显示“已连接 / 重连中”。
- 失败、过期、不支持的值显示为空，不会当成 0 参与排行和判断。

## 告警规则

“告警中心 → 告警规则 → 新增告警规则”。

| 字段 | 说明 |
| --- | --- |
| 规则类型 | 指标阈值：按指标数值判断；可达性失败：管理端点连续多次连不上 |
| 告警级别 | 严重 / 警告 / 提示，决定颜色、排序和通知路由 |
| 指标键 | 要判断的指标，可用 `*` 通配，如 `cpu.temp`、`disk.used_pct:*`、`fan.rpm:*`。实际的键在资产的“指标与采集”里看 |
| 触发方向 / 阈值 | 大于等于或小于等于阈值时触发 |
| 恢复阈值 | 回到这个值才算恢复，默认触发阈值减 5，避免在阈值附近来回跳 |
| 连续样本数 / 持续时间 | 连续多少次、持续多久都超阈值才触发，过滤偶发尖峰 |
| 冷却时间 | 恢复后这段时间内再触发不重新通知，默认 60 秒 |
| 重复提醒 | 一直未处理时每隔多久再通知，`0` 为只通知一次 |
| 资产标签 / 限定资产 | 只对部分资产生效；都不填对全部资产生效 |
| 上游依赖故障时抑制下游通知 | 宿主或上联设备已在告警时，下游资产的告警照常记录但不单独发通知（默认开启） |

可达性规则只在全部非控制端点都超时或不可达时才判定；认证失败、缺凭据、证书不受信、数据过期都不能证明设备离线。

内置的默认规则包括：硬件 CPU 高温、系统 CPU / 内存 / Swap / 根分区使用率、管理端点持续不可达、服务器出现严重硬件事件、虚拟化备份失败、UPS 转为电池供电、巡检发现严重异常、维护超过预计结束时间。都可以修改或停用。

告警状态：待满足条件 → 告警中 → 已确认 / 已静默 → 已恢复。确认表示有人在处理；静默表示一段时间内不再通知。

## 通知渠道

“告警中心 → 通知与投递”。支持邮件（SMTP）、通用 Webhook、Server 酱、钉钉、飞书、企业微信、Bark、PushPlus。

- 所有渠道新建时默认停用，启用后才发送。
- 邮件：TLS 通常 465 端口，STARTTLS 通常 587；QQ、163 等邮箱填**授权码**而不是登录密码。
- 机器人开启“加签”时填签名密钥。
- 路由标签：只把带这些标签的资产的告警发到这个渠道；也可以按严重程度路由。
- 合并窗口：这段时间内的多条告警合并成一条发送。
- 通知模板可以自定义标题与正文，使用 `{{asset}}`、`{{title}}`、`{{severity}}`、`{{value}}` 等变量。
- 保存后点“测试通知”验证。投递失败的记录可以“重试投递”；结果不确定的（可能已经送达）需要确认后才重发。

## 维护窗口

计划内停机或升级时使用：“告警中心 → 维护窗口”。

- 窗口内匹配的资产**照常采集和记录告警，但不发通知**。
- 窗口可以修改，时间带时区。
- 可以限定资产、标签，同时选了时取两者都满足的资产。**都不选时必须勾选“对全部资产生效”才能保存**，防止误把全部资产静音。
- 窗口结束后：仍在告警的会补发通知；窗口期间已经恢复的告警，**只有之前确实发出过触发通知**的，才在窗口结束后补发一次恢复通知（从没通知过的不会凭空收到“已恢复”）。
- 管理员和运维可以管理；只对“可见全部资产”的账号开放。

## 资产维护中与超期提醒

把资产的生命周期改为“维护中”时，要填**预计结束时间**（默认 7 天后）。

- 维护中的资产停止定时采集，不产生新告警，也不能控制和巡检；之前已有的告警保留，但不发通知。
- 过了预计结束时间仍是“维护中”：默认规则“维护超过预计结束时间”照常告警并通知，总览的告警和每日巡检报告里也会列出。
- 这只是提醒，不会自动改回“在用”。延长预计结束时间或改回“在用”后提醒结束。
- 只想一段时间不收通知、仍要看到读数时，用上面的维护窗口。

生命周期的其他状态见 [资产与回收站](assets-recycle.md)。

## 服务器告警

“服务器告警”板块逐条显示服务器 BMC 的硬件事件日志：

- 来源：Redfish 每次采集读最近 100 条；没有 Redfish 时 IPMI 低频读取；可选 SNMP Trap 与 Redfish 事件推送（见 [设备接入](devices.md)）。都只读，**从不清空 BMC 上的日志**。
- 按关键词分类：温度、风扇、电源、内存、硬盘与阵列、CPU、机箱；按状态、级别、类别、资产筛选。
- 首次读到时，近 7 天的严重 / 警告为“待处理”，更早的或提示类为“已归档”。保留 180 天。
- 运维以上可以把事件标记为“已处理”，必须写处理结果，写入审计。只改平台里的状态。
- 默认规则“服务器出现严重硬件事件”：有待处理的严重事件就告警；已通知过又来了新的严重事件时再提醒一次；全部标记已处理后恢复。

## 每日巡检报告

“巡检 → 每日巡检报告”。每天本地时间 8 点后自动生成一份（`YUNSHU_INSPECTION_HOUR` 可改，`-1` 关闭），运维可随时“立即巡检”。

检查内容：采集失败或全部过期、CPU 温度、整机 / 电源模块 / 内存 / 硬盘 / RAID / UPS 电池健康、风扇停转、磁盘与存储池容量、备份失败与久未成功、复制出错、UPS 电池供电、服务器告警里待处理的严重事件、未处理告警、维护超期。温度与容量优先按覆盖该资产的告警规则判断，没有规则时用固定值（CPU 70 / 80 ℃，磁盘与存储池 80% / 90%）。

报告可以导出 CSV（Excel 直接打开），或“打印 / 另存 PDF”。报告按查看人的资产范围过滤，保留 90 天。

## 命令巡检

“巡检”页面的“巡检模板 / 巡检任务 / 执行记录”：经 SSH 在设备上执行**只读**命令，逐项判定结果。

**模板**

- 内置五个只读模板：Linux、Proxmox VE、华为（VRP）、H3C（Comware）、Cisco（IOS）。未实机验证。
- 管理员可以复制后自定义。保存时**拦截危险命令**：删除 / 移动文件、重启关机、分区格式化、启停服务、结束进程、改权限与用户、写文件与重定向、装卸软件、改虚拟机 / 存储池 / 集群、挂载与网络配置、下载执行脚本等；华为 / H3C 只允许 `display` 类命令，Cisco 只允许 `show` 类命令，拦截进入配置模式和 reset / delete / save / undo / write / reload。
- 保存自定义模板要输入模板名称确认，写入审计（含全部命令）。执行前还会再按危险命令清单检查一次。
- 建议给巡检用专用的只读账号：命令能做什么最终取决于账号权限。

**判定方式**：只记录输出；输出为空算正常；匹配正则算正常 / 算异常；数值阈值（用正则第一个括号取数值，设警告值与严重值）；退出码为 0 算正常（仅 Linux / PVE）。命令不存在时记为“无法判断”。

**任务**

| 执行方式 | 说明 |
| --- | --- |
| 单次 | 立即执行，或指定一个时间执行一次；执行后自动停用 |
| 每天 / 每周 / 每月 | 按平台时区在指定时间执行；每月选 31 日时，小月在最后一天执行 |
| 高级（cron 表达式） | 5 段：分 时 日 月 星期，例如 `30 8 * * 1-5` 为工作日 08:30 |

- 运维和管理员可以建任务、立即执行，所选设备必须都在自己的资产范围内。
- 只使用用途为“监控”或“管理”、已关联凭据的 SSH 端点；首次连接时信任并记住主机密钥。
- 单条命令默认 30 秒超时，一台设备最长 15 分钟；每条输出最多保存 64 KB；执行记录保留 90 天，可以和上一次的输出对比。

**告警**：只有判为“严重”的异常会生成告警（默认规则“巡检发现严重异常”），下一次巡检正常后恢复；警告和提示只出现在执行记录里。

## 漏洞情报

“漏洞情报”页面：收集公开漏洞，按本地设备的固件与软件包版本判断影响。

- **外网同步默认关闭**。关闭时平台不访问任何漏洞网站，只能导入离线包或接收推送。打开后只下载数据，不上传资产信息（OSV 查询会发送软件包名与版本）。
- **数据源逐个启用**：CVE 官方记录、NVD（可填免费 API 密钥加快同步）、CISA KEV（已被利用）、OSV、EPSS、GitHub 安全公告、长亭 / OSCS / 奇安信 / 微步等国内来源、厂商安全公告 RSS、watchvuln 推送。国内来源和厂商公告默认不启用；国内来源使用网站的非正式接口，网站改版时可能失效。
- **离线包**：在能上网的机器上生成 zip，再在平台导入，适合内网。
- **订阅**：按“厂商:产品”（与 NVD 的 CPE 写法一致，如 `openbsd:openssh`）或关键词订阅，可设最低严重程度。
- **本地影响**：比对已识别版本的固件和软件包（SSH 软件包清单见 [设备接入](devices.md)）。没有修复版本的漏洞只标“可能受影响”。
- **修复信息**：汇总各来源原文中的修复版本、修复建议与临时缓解措施，以及补丁 / 厂商公告链接。
- **处置状态**：待处理、确认受影响、不受影响、已缓解、接受风险、误报。只有管理员能修改，每次修改写审计；已缓解和接受风险到了复查日期自动回到待处理。

**通知**（走告警中心的通知渠道）：

- 同一漏洞只发一条消息，列出受影响资产和**所有发布来源**。新漏洞第一次出现后等一个汇总窗口（默认 5 分钟），让几乎同时发布的其他来源并入同一条；之后才出现的来源只更新详情和每日汇总。
- 订阅命中预警：新漏洞命中订阅、已被利用或为严重级别、但还没有版本数据能确认时，先发“漏洞预警·待确认”，确认命中后再发“漏洞确认”。
- 每日汇总：新漏洞、新命中、待处理与到期复查数量。

数据源、订阅、离线包导入和通知设置只有管理员能修改。

## AI 助手（可选，默认关闭）

在“平台设置 → AI”由管理员配置。

- **默认关闭**。打开总开关后，还要逐个开启功能：漏洞影响分析、告警解读、巡检报告摘要、问答助手（顶栏“问云枢”）。
- **只读**：AI 只负责解释、汇总和建议，只能使用只读工具，**不能执行任何操作**；是否受影响、是否告警等判断由程序完成。回答按提问人的资产范围过滤。
- **隐私模式**：默认“脱敏”，发送前把资产名、主机名、IP、MAC、序列号替换成代号，回答后在本地换回；“完整”只建议用于本机或内网模型。无论哪种模式，设备密码、密钥、令牌都不会发送。
- **模型接口**：支持 OpenAI 兼容、Claude、Gemini、Azure 四种协议，预置多家国内外厂商与 Ollama 等本地模型；每个功能可以指定不同接口。保存后先做“连接自检”。公网接口必须用 https。
- **调用上限**：24 小时内的调用次数和 token 总数上限（默认 200 次、50 万 token），达到后暂停调用，只显示程序算出的结果。
- 默认只记录调用的时间、功能、模型、耗时和 token 数；“记录调用内容”默认关闭。

**只读 MCP 接口**：供外部 AI 工具查询本平台，地址 `https://<平台地址>/mcp`，请求头带 `Authorization: Bearer <只读 API 令牌>`。需要在 AI 设置里单独开启，不使用这里的模型接口，也不受总开关影响。令牌见 [用户、角色与资产范围](users-scope.md)。

## Prometheus 与 Grafana

1. “平台设置 → API 令牌”创建只读令牌（只显示一次）。
2. 在 Prometheus 中添加：

```yaml
- job_name: yunshu
  scheme: https
  metrics_path: /metrics
  authorization:
    credentials: fake-token-replace-me
  static_configs:
    - targets: ["yunshu.example.test"]
```

导出的是令牌所属账号可见资产的有效最新数值，指标名形如 `yunshu_cpu_temp`，标签有 `asset`、`asset_id`、`item`、`unit`。抓取间隔建议不小于 60 秒。
