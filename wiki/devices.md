# 设备接入

## 基本概念

- **资产**：一台被管理的设备。形态（物理机 / 虚拟机 / 容器）、角色（服务器、交换机、路由器、UPS、NAS……）、平台（debian、proxmox、dell-idrac……）三项互相独立。
- **管理端点**：连接这台设备的方式。一台资产可以有多个，例如 iDRAC 的 SNMP、Redfish 和 IPMI。每个端点有**用途**：
  - 监控：只用来读数据；
  - 控制：用来开关机、调风扇等写操作；
  - 管理：两者都可以。

  只读账号和有写权限的账号可以分开放在同一地址的两个端点上。控制端点还可以“关联只读凭据”，执行控制前后查状态时用它。
- **凭据**：账号密码、团体名、SNMPv3 账号、SSH 私钥或 API 令牌。加密保存，可以被多台设备共用；保存后页面和接口都不再显示明文。共用凭据改了以后，所有用它的设备都用新值。
- **采集模板**：决定用哪些协议、按什么顺序采集。一般按平台和端点自动选择，不用手动指定。

## 添加设备

1. “资产管理 → 资产列表 → 新增资产”。
2. 选择协议，填设备地址（只填 IP 或主机名）和端口，选择已有凭据或填写新凭据。
3. 可以先点“获取设备信息”，从设备上只读取品牌、型号、序列号、主机名，再逐项勾选是否填入。
4. 保存后在资产详情的“指标与采集”查看各协议的采集状态。

只有生命周期为“在用”的资产会被定时采集，见 [资产与回收站](assets-recycle.md)。

批量添加：

- **批量导入**：按设备类别下载模板（xlsx / csv），填好后上传，先预览再提交，见 [资产与回收站](assets-recycle.md)。
- **网段发现**：“监控中心 → 网段发现”，输入授权范围（如 `192.0.2.0/24`），用 TCP 端口或只读 SNMP 探测，再逐台确认建档。先“预览范围”不联网核对地址数量。只扫描你有权管理的网络。

## 各类设备怎么接

| 设备 | 采集模板 | 推荐协议 | 设备上要做的准备 |
| --- | --- | --- | --- |
| Dell 服务器 / iDRAC | `dell-server` | **SNMP**（主）+ Redfish（补充，每 10 个周期）+ IPMI（回退） | iDRAC 开启 SNMP 代理，建 SNMPv3 只读用户（认证 + 加密）；可选 Redfish 只读账号；IPMI 只读账号作回退 |
| 其他品牌 BMC | `generic-bmc` | Redfish（主）+ SNMP（补充）+ IPMI（兜底） | Redfish 只读账号；有 SNMP 时开启；IPMI over LAN 只读账号。默认 5 分钟采集一次 |
| Debian / Ubuntu | `linux` | SNMP 或 SSH | 安装 snmpd 只读，或提供 SSH 只读账号 |
| Alpine / Rocky / AlmaLinux | `linux-b` | SNMP 或 SSH | 同上 |
| OpenWrt / iStoreOS | `openwrt` | SNMP 或 SSH | 安装 snmpd，或开启 SSH |
| 交换机 / 路由器 | `snmp-switch` | SNMP | 开启 SNMP 只读；需要拓扑时开启 LLDP |
| MikroTik RouterOS | `routeros` | SNMP | `/snmp` 开启，推荐 v3 只读 |
| Proxmox VE | `pve` | PVE API（可加 SSH） | 建 API 令牌，角色至少 PVEAuditor；要读备份任务需 `Sys.Audit` |
| VMware ESXi / vCenter | `esxi` | vSphere API | 只读角色账号 |
| UPS（带网卡） | `ups-snmp` | SNMP（UPS-MIB） | UPS 网卡开启 SNMP |
| 群晖 NAS | `nas-synology` | SNMP | DSM“终端机和 SNMP”中开启，推荐 v3 |
| 只能 ping / 连端口的设备 | `reachability` | TCP 可达性 | 只需要一个开放的端口 |

> 所有模板目前都是“未实机验证”：按公开协议定义和模拟数据开发。读不到的字段显示“不支持”，不会显示为 0。

### 为什么 Dell 服务器推荐 SNMP

IPMI 每次采集都要登录再登出，iDRAC 的 Lifecycle 日志会被大量“登录 / 登出”记录刷满。SNMP 是无会话的问答，不产生登录记录；iDRAC 的 SNMP（IDRAC-MIB）能读到温度、风扇、电源模块、内存、硬盘和 RAID 状态。开关机和风扇调速仍然走 IPMI / Redfish（SNMP 只读）。

## 服务器的采集计划

Dell 与通用 BMC 模板的服务器，只要同时有**两个以上 BMC 协议**（SNMP / Redfish / IPMI）的非控制端点，就不再按模板步骤采集，而是按自动生成的**采集计划**：

1. 第一次把每个协议都只读地读一遍，记下各自真正能读到哪些数据：温度、风扇、功耗与电源、整机与部件健康、硬盘与阵列、BMC 日志、清单。
2. 每项数据挑一个**主来源**和兜底：高频数据按 SNMP → Redfish → IPMI 的顺序优先，低频数据按 Redfish → SNMP → IPMI。
3. 之后每个周期只连接“到期数据的主来源”；主来源失败时，它负责的数据交给下一个协议，指标上标“降级”。低频数据每 10 个周期采一次。
4. 计划里不负责任何数据的协议不再连接，状态显示“跳过”并说明原因。

端点变化、超过 7 天、上次探测有协议不可用（每小时再试）时自动重新探测；也可以在资产的“指标与采集”里点“重新探测”。

另外两项省 BMC 的机制：

- **每台 BMC 排队与限速**：同一台 BMC 的采集、控制操作和“获取设备信息”排队，同一时刻只有一个在访问；控制优先。定时采集每台 BMC 每分钟最多 Redfish 2 次、IPMI 1 次（`YUNSHU_BMC_RATE`），超出的本轮顺延，不算失败。
- **临时提频**：资产有未结束的阈值告警、指标已在阈值 10% 以内，或收到 BMC 推送的严重 / 警告事件时，每 15 秒采集一次，持续到条件消失后 10 分钟；同时最多 10 台（`YUNSHU_BOOST_MAX`）。仍受上面的限速约束，所以主要加快 SNMP。
- **双来源核对**：温度与功耗每天用主来源和另一个协议各读一次比对；差得太多且 Redfish 能读到时，该项改由 Redfish 提供，并提示“该品牌 MIB 对应可能有误”。

## BMC 推送事件（默认关闭）

平台默认定时读取 BMC 系统事件日志（SEL），在“服务器告警”板块逐条显示。想让 BMC 出现硬件告警时**立即**推送过来，可以打开下面两种接收方式：

| 方式 | 部署设置 | 说明 |
| --- | --- | --- |
| SNMP Trap | `YUNSHU_SNMP_TRAP=1`、`YUNSHU_SNMP_TRAP_TARGET=<BMC 能访问到的平台 IP>`；Docker 端口映射 `162:1162/udp` | Worker 监听 UDP 1162（不需要特权端口）。只收 v1 / v2c；来源 IP 必须是某台资产 SNMP / Redfish / IPMI 端点的 IP，团体名要对得上，否则丢弃。每来源每分钟最多 60 条 |
| Redfish 事件 | `YUNSHU_BMC_EVENTS_URL=https://<BMC 能访问到的平台地址>` | BMC 推送到 `/api/bmc-events/<随机令牌>`，必须经 HTTPS 反向代理；只需对 BMC 网段放行这一个路径 |

然后在“运维操作 → 开启 SNMP”里对服务器执行“在 BMC 上配置 Trap 目标”或“订阅 BMC 的 Redfish 事件”。这一步会写 BMC 配置，需要部署设置 `YUNSHU_BMC_SNMP=1`，并且只有管理员能执行，见 [运维操作](operations.md)。

- Linux 原生安装没有端口映射，要在主机防火墙上把 UDP 162 转发到 1162（firewalld 或 nftables），命令见 [Linux 安装说明](https://github.com/kongbai9420/YunShu/blob/main/deploy/linux/README.md)。
- SNMPv3 Trap 暂不支持。
- 推送只写“服务器告警”，不触发任何设备操作。推送与定时读取到的同一条事件，2 分钟内文字相同的只保存一次。

## 软件包清单（SSH）

在 Linux 主机的 SSH 端点上勾选“读取软件包清单”后，平台**每天**用这个 SSH 账号执行一次只读命令（`dpkg-query`、`apk` 或 `rpm`），记录已安装的软件包和版本，显示在资产详情的“软件与版本”里，并用于[漏洞情报](monitoring-alerts.md)比对。

- 默认关闭；不需要 root 权限，不修改设备。
- 每天会多一次 SSH 登录，设备的登录日志里会留下记录。
- 目前 Debian、Ubuntu、Proxmox VE 主机能做软件包漏洞比对。

## SNMPv3 参数

| 参数 | 说明 |
| --- | --- |
| 用户名 | 设备上建的 SNMPv3 用户 |
| 认证算法 / 认证密码 | 与设备一致，默认 SHA，较新设备支持 SHA-256；认证密码至少 8 位 |
| 加密算法 / 加密密码 | 与设备一致，默认 AES（128 位）；留空表示只认证不加密 |

v2c 的团体名在网络上是明文，只建议在隔离的管理网使用。

## 证书与主机密钥

- HTTPS 设备（Redfish、PVE、vSphere）：第一次连接时记住证书指纹，以后证书变了就拒绝连接，防止中间人冒充。设备更换证书后，在端点上“信任新证书”。
- SSH：同样记住主机密钥；先比对主机密钥，一致或首次才发送密码。

## 采集状态

| 状态 | 含义 |
| --- | --- |
| 正常 | 最近一次采集成功 |
| 失败 | 连接、认证或协议出错，详情里有原因；首选协议失败后按 2 / 4 / 8 个周期冷却重试，最长 10 分钟。“立即采集”会提前重试 |
| 未配置 | 端点没有凭据，没有连接设备 |
| 身份不受信 | 证书或主机密钥与之前记住的不一致 |
| 降级 | 首选协议不可用，正在用备用协议 |
| 跳过 | 采集计划里这个协议不负责任何数据，不再连接 |
| 过期 | 超过 3 个采集周期没有新数据 |

某个来源采集失败时，它以前报过的指标显示为“失败”（值为空），不会显示旧值或 0。
