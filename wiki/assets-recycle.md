# 资产与回收站

## 资产的三个维度

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 形态 | 物理机、虚拟机、容器 | 资产的存在形式 |
| 角色 | 服务器、交换机、路由器、AP、防火墙、NAS、存储、UPS、其他 | 决定列表分类、拓扑图标和自动推断的采集模板 |
| 平台 | 自由文本，如 `debian`、`proxmox`、`dell-idrac` | 用来推断采集模板和比对漏洞 |

三项互相独立。例如一台跑 Proxmox 的服务器：形态是物理机，角色是服务器，平台是 proxmox。

- **资产编号**全平台唯一，是批量导入时判断新增还是更新的依据。平台**不按 IP 合并**资产：同一个管理地址可以属于多台资产。
- **资产关系**：承载（宿主承载虚拟机）、安装于、属于、依赖。总览、拓扑、告警抑制和关机影响提示都依据这些关系。
- 修改资产时会检查版本：别人在你编辑期间保存过，会提示冲突，不会静默覆盖。

## 生命周期

| 状态 | 定时采集 | 新告警 | 控制与巡检 | 说明 |
| --- | --- | --- | --- | --- |
| 在用 | 是 | 是 | 可以 | 默认状态 |
| 规划中 | 否 | 否 | 不可以 | 还没投入使用；从虚拟化发现新建的资产默认是规划中 |
| 维护中 | 否 | 否 | 不可以 | 要填**预计结束时间**（默认 7 天后），超期会提醒 |
| 已退役 | 否 | 否 | 不可以 | 不再使用，历史数据保留 |

- 改为规划中、维护中或已退役后，之前已有的告警保留，但不发通知。改回“在用”后恢复采集和告警。
- **维护中超期提醒**：过了预计结束时间还是维护中，默认规则“维护超过预计结束时间”告警并通知，总览和每日巡检报告里也会列出。只是提醒，不会自动改回在用；延长时间或改回在用后提醒结束。
- 只想一段时间不收通知、仍要采集和看到读数时，用告警中心的“维护窗口”，见 [监控、告警与巡检](monitoring-alerts.md)。

## 回收站

删除资产**不会立即删掉**，而是移进回收站：

- 资产在所有列表、计数、拓扑、关系里都当作不存在，采集、控制、巡检、漏洞比对也都跳过它。
- 保留期内可以恢复，恢复后回到删除前的生命周期（从维护中删除的，恢复后预计结束时间为 7 天后）。
- 保留期满后，平台每小时检查一次，**彻底删除**，连同管理端点和关联，不能再恢复。
- 回收站里的资产仍占用它的资产编号。

入口：“资产管理 → 资产列表”右上角的“回收站”按钮（只读账号看不到）。

| 操作 | 谁能做 |
| --- | --- |
| 删除资产（移入回收站） | 运维、管理员 |
| 从回收站恢复 | 运维、管理员 |
| 提前彻底删除 | 只有管理员 |
| 修改保留天数 | 只有管理员 |

**保留天数**默认 30 天，可设 1–365 天，在回收站页面修改。改短后，已在回收站里、超过新期限的资产会在下一次清理（一小时内）彻底删除，请谨慎。

## 批量导入

“资产管理 → 批量导入”：

1. 按设备类别下载模板：物理服务器、Linux 服务器、交换机、路由器、通用，`.xlsx` 或 `.csv`。
2. 填好后上传，先看**预览**：逐行标出新增 / 更新 / 无变化 / 冲突 / 无效，这一步不改资产。
3. 确认后提交；需要时可以“撤销”整批。

规则：

- **资产编号必填**，是唯一的去重键；同一文件里重复的编号标为冲突。不按 IP 合并。
- 更新只改填了值的列；预览后到提交前资产被别人改过的行标为冲突、不覆盖。
- 撤销只处理导入后没再被修改过的行，改过的保留并在结果里说明；本批新建的空场所一并删除。
- “关联资产编号”表示承载本资产的宿主，可以引用同一文件里的资产。
- 模板**不含密码列**，凭据用“凭据别名”引用已经建好的凭据。
- 限制：5 MB、5000 行；只收 `.csv`（UTF-8 或 GBK）和 `.xlsx`；XLSX 里带公式的单元格整行无效。
- 每一批的结果可以导出 CSV。

另外两种建档方式：

- **网段发现**（“监控中心 → 网段发现”）：扫描授权网段，逐台确认后建档，见 [设备接入](devices.md)。
- **从 3.x 旧版导入**：用 `legacy_import` 命令，见 [备份、升级与迁移](backup-upgrade.md)。
