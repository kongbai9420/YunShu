# 总览、拓扑与机柜

## 总览

“总览”有三个视角：

- **仪表盘**：资产采集状态分布、当前告警与最近采集问题、CPU 温度排行、功耗（当前与近 1 小时）、指标质量分布、关注列表。可以拖动调整布局（运维以上），所有人共用一份布局。失败、过期、不支持的值不进排行、不当成 0。
- **资源全景**：所有资产按类别排成卡片或长条，显示宿主与其上的虚拟机、采集状态、电源和告警；可以按场所、类别、形态、生命周期、平台、标签筛选，也可以拖动调整显示顺序。物理服务器卡片上有“电源操作”快捷入口。
- **拓扑视图**：网络连线图，见下文。

多人同时编辑布局时，后保存的人会看到冲突提示，可以选择“载入最新”或“用我的版本覆盖”，系统不会静默覆盖。

### 虚拟资源发现与关联

PVE / vSphere 采集成功后，“资源全景 → 虚拟资源发现与关联”列出平台上的宿主、虚拟机和容器。平台不会自动建档或按名称、IP 合并：

1. 先确认宿主。
2. 对每台虚拟机 / 容器预览后选择：新建资产并关联、关联到已有资产、忽略候选，或解除平台绑定（保留资产）。
3. 确认后建立“宿主承载”关系。新建的资产为“规划中”，没有端点和凭据。

人工建立的关系不会被自动发现覆盖。承载关系会用于告警的上游抑制、关机影响提示和“关宿主前先关虚拟机”。

## 拓扑

链路分三类：

| 类型 | 来源 | 重新扫描时 |
| --- | --- | --- |
| 候选（细虚线） | 交换机 SNMP 采集到的 LLDP 邻居 | 可能新增、更新或移除 |
| 已确认（实线） | 人工确认过的候选 | 不会改动 |
| 人工（粗实线） | 手动添加的连线 | 不会改动 |

- “重新扫描”只用已经采集到的 LLDP 邻居表，不连接设备；先显示差异预览，确认后才合并。
- 远端名称按资产名称或采集到的主机名匹配（不区分大小写），**不按 IP 匹配或合并资产**；对不上的列为“未匹配”。
- 同一对设备之间有多条线时，两端端口写在同一条候选里；手动连线填上端口即可区分。
- 不想再看到的候选可以“忽略”，以后不再提出。
- 可以建多个视图（如“家庭网络”“机房”），每个视图有自己的布局，可以只显示某个场所的资产；删除视图或把节点移出视图都不会删除资产和链路。
- “自动布局”整理画布，锁定的节点不会被移动。

## 场所与机柜

“平台设置 → 场所”建立场所层级（园区 → 机房 → 房间），场所下建机柜（填高度，单位 U）。

在资产的“编辑”里填：机柜、起始 U 位（设备最下面一个 U 的编号，从 1 开始自下而上）、设备型号、安装面（正面 / 背面）。

- 占用多少 U 由**设备型号**的 U 高决定；没有指定型号时按 1U、全深计算。
- 全深设备前后两面都占；半深设备只占一面，前后可以各装一台；0U 设备（如竖装 PDU）不占 U 位。
- 越界或与其他设备重叠时无法保存，并提示被谁占用。

“机柜与定位 → 机柜”查看每个机柜的正面 / 背面视图、空余 U 数和当前功耗；点设备名称直接打开资产详情。

## 设备型号库

“机柜与定位 → 设备型号”：

- 手工添加型号（厂商、型号、U 高、是否全深）。
- 或由管理员导入社区维护的 [devicetype-library](https://github.com/netbox-community/devicetype-library)（CC0 公有领域）：在 GitHub 下载该仓库的 ZIP 后上传，可只导入指定厂商。重复导入只更新变化的型号，手工录入的型号不会被覆盖。

## 按 MAC / IP 查找端口

“机柜与定位 → 查找 MAC / IP”：输入 MAC 地址或 IP，显示它最后出现在哪台交换机的哪个端口。

- 数据来自交换机的 MAC 地址表和 ARP 表（交换机要开启 SNMP 并被采集），每台交换机约 10 分钟更新一次，离线后保留最后位置 7 天。
- 一个端口学到的 MAC 越少越可能是接入口；学到很多 MAC 或有 LLDP 邻居的端口标为“上联口”，排在后面。
- 只作参考证据，不会据此合并资产或认定连线。
